# 2026年9月3日 嵌入式系统开发实验笔记

## 一、实验概览

今日实验主要围绕 Hi3861 + STM32 双芯片小车系统的红外避障功能展开。通过 TCRT5000 红外反射传感器检测前方障碍物，由 Hi3861 进行决策并通过串口发送指令，STM32 执行电机控制，实现小车自主避障。

---

## 二、双芯片系统架构

### 2.1 为什么需要两个芯片？

| 芯片 | 角色 | 职责 |
|------|------|------|
| **Hi3861（鸿蒙）** | 大脑（决策层） | 传感器数据采集、避障算法、指令生成 |
| **STM32（小车）** | 手脚（执行层） | 串口指令接收、PID 控制、PWM 电机驱动 |

### 2.2 通信方式

| 项目 | 说明 |
|------|------|
| 通信接口 | UART 串口（异步串行通信） |
| Hi3861 发送引脚 | GPIO_6（UART1_TX） |
| STM32 接收引脚 | PB8（软件模拟串口 RX） |
| 波特率 | 115200 bps（最终统一） |
| 数据格式 | 8 位数据位，1 位停止位，无校验（8N1） |

### 2.3 通信协议格式

Hi3861 发送的帧格式：

| 字节 | 内容 | 说明 |
|------|------|------|
| Byte 0 | `0xA5` | 帧头 1 |
| Byte 1 | `0x5A` | 帧头 2 |
| Byte 2 | `SEQ` | 序列号（防重复） |
| Byte 3 | `CMD` | 控制指令 |
| Byte 4 | `XOR` | 校验和 |

**指令定义：**

| 指令 | 含义 | 对应动作 |
|------|------|----------|
| `'F'` | FORWARD | 前进 |
| `'B'` | REVERSE | 后退 |
| `'L'` | LEFT | 左转 |
| `'R'` | RIGHT | 右转 |
| `'S'` | STOP | 停止 |

## 三、红外传感器 TCRT5000

### 3.1 工作原理

TCRT5000 是一种红外反射式传感器，包含红外发射管和接收管。

| 表面颜色 | 反射率 | 传感器输出 |
|----------|--------|-----------|
| 白色/浅色 | 高 | 低电平（或高电平，视电路而定） |
| 黑色/深色 | 低（红外被吸收） | 相反电平 |

### 3.2 避障应用

将 TCRT5000 安装在车头朝下或朝前，检测前方是否有障碍物：

| 检测结果 | 判断 | 小车动作 |
|----------|------|----------|
| 前方无物体（反射弱） | 安全 | 前进 |
| 前方有障碍物（反射强） | 有障碍 | 停止 → 后退 → 转向 |

## 四、Hi3861 端代码逻辑

### 4.1 主程序流程

```
系统启动
    │
    ▼
初始化：GPIO、UART、看门狗
    │
    ▼
创建障碍物检测任务
    │
    ▼
循环执行：
    读取传感器数据（红外距离）
    │
    ▼
障碍物控制器决策：
    ├── 距离 < 阈值 → 停止 → 后退 → 转向
    └── 距离 ≥ 阈值 → 前进
    │
    ▼
通过串口发送指令给 STM32
    │
    ▼
延迟 20ms 继续循环
```

### 4.2 避障状态机

| 状态 | 触发条件 | 动作 |
|------|----------|------|
| FORWARD（前进） | 前方安全 | 发送 `'F'` |
| STOP（停止） | 前方有障碍 | 等待 500ms，然后转向 |
| TURN_LEFT/RIGHT（转向） | 随机选择方向 | 转向持续 2 秒 |
| PROBE（探测） | 转向完成 | 探测前方是否安全 |

### 4.3 关键参数

| 参数 | 值 | 含义 |
|------|-----|------|
| 障碍物阈值 | 20cm | 小于此值触发避障 |
| 清障阈值 | 25cm | 大于此值恢复前进 |
| 停止时间 | 500ms | 遇到障碍后暂停时间 |
| 转向时间 | 2s | 转向持续时间 |
| 控制循环 | 20ms | 每次决策间隔 |

## 五、STM32 端代码逻辑

### 5.1 主程序流程

```
系统启动
    │
    ▼
初始化：时钟、PWM、软串口
    │
    ▼
进入主循环：
    等待软串口接收字节
    │
    ▼
解析协议帧（A5 5A SEQ CMD XOR）
    │
    ▼
提取指令（'F'/'B'/'L'/'R'/'S'）
    │
    ▼
执行对应动作：
    调用 Set_Pwm() 控制电机
```

### 5.2 软件串口（Soft UART）实现

由于 Hi3861 的 UART 输出接 STM32 的 PB8，而 PB8 不是硬件 UART 引脚，因此使用**软件模拟串口**接收数据。

**实现原理：**

1. 使用外部中断检测起始位（下降沿）
2. 使用定时器（TIM3）精确延时采样
3. 逐位读取数据位（8 位）
4. 校验停止位

**关键参数（115200 波特率）：**

| 参数 | 值 | 说明 |
|------|-----|------|
| 位时间 | ~8.68us | 1 / 115200 |
| 起始采样点 | 13us | 约 1.5 倍位时间 |
| 后续采样间隔 | 9us | 每个数据位采样一次 |

### 5.3 电机控制

| 动作 | 左轮 | 右轮 | 效果 |
|------|------|------|------|
| 前进 | 正转 | 正转 | 直行 |
| 后退 | 反转 | 反转 | 后退 |
| 左转 | 反转 | 正转 | 原地左转 |
| 右转 | 正转 | 反转 | 原地右转 |
| 停止 | 停止 | 停止 | 停车 |

## 六、波特率配置

### 6.1 配置过程

| 设备 | 文件 | 修改内容 |
|------|------|----------|
| Hi3861 | `car_uart.c` | `CAR_UART_BAUD_RATE 2400` → `115200` |
| Hi3861 | `Hcsr04ObstacleApp.c` | 打印信息 `2400` → `115200` |
| STM32 | `soft_uart_rx.c` | `BAUD_RATE 2400` → `115200` |
| STM32 | `soft_uart_rx.c` | `BIT_TIME_US` 重新计算 |

### 6.2 位时间计算

| 波特率 | 位时间 | 采样点 |
|--------|--------|--------|
| 2400 | ~416.67us | ~625us |
| 115200 | ~8.68us | ~13us |

**计算方式：**
```
BIT_TIME_US = 1000000 / BAUD_RATE
FIRST_SAMPLE_US = BIT_TIME_US * 1.5
```

## 九、常见问题与解决

### Q1：小车不响应 Hi3861 指令

| 原因 | 解决方法 |
|------|----------|
| 波特率不匹配 | 确认 Hi3861 和 STM32 都是 115200 |
| 引脚接错 | Hi3861 GPIO_6 → STM32 PB8 |
| 没共地 | 连接 GND |
| STM32 未初始化 | 检查 `PWM_Init()` 是否调用 |

### Q2：小车只动一下就不动了

| 原因 | 解决方法 |
|------|----------|
| 电池没电 | 换新电池 |
| 驱动板供电不足 | 确保驱动板接电池 |
| 代码进入安全停止 | 检查串口通信是否稳定 |

### Q3：串口打印乱码

| 原因 | 解决方法 |
|------|----------|
| 波特率不对 | 确认串口助手波特率 = 115200 |
| 编码问题 | 串口助手选 UTF-8 或 GBK |

## 十、实验小结

本次实验完成了 Hi3861 + STM32 双芯片小车系统的红外避障功能。核心收获包括：

1. **理解了双芯片分工的优势**：Hi3861 专注于无线通信与决策，STM32 专注于电机控制，各司其职。

2. **掌握了 UART 通信协议的设计**：通过 `A5 5A SEQ CMD XOR` 帧格式，实现了稳定可靠的数据传输。

3. **学会了软件串口的实现原理**：利用外部中断和定时器，在任意 GPIO 引脚上模拟 UART 接收。

4. **建立了完整的嵌入式系统调试思路**：从硬件排查 → 波特率确认 → 串口打印 → 逐步定位问题。

5. **避障算法的基本实现**：通过传感器检测 → 状态机决策 → 电机执行，完成了完整的闭环控制。
